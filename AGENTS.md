## GCP VM access

**Repo writers can log in with full sudo.** From the repo root, run the helper below on a machine with Python 3, OpenSSH and GitHub CLI signed into a repo writer's account (`gh auth login` if needed). Any writer can request a certificate, including when the VM owner is offline.

```sh
./scripts/vm-ssh
```

For an unattended check, run `./scripts/vm-ssh 'hostname && id -un && sudo -n id -u'`. Expect `instance-20261122-003928`, `lio-team` and `0`. The shared checkout is at `~/work/lio-supply-chain-automation`. Each workstation generates its own key under `~/.ssh/lio-team-vm/`. GitHub Actions signs its public key for eight hours and records the requesting GitHub identity in the certificate. The helper reuses a valid certificate on subsequent connections.

The signer is stored in the encrypted Actions secret `LIO_VM_USER_CA`. To stop new sign-ins immediately, an administrator can remove its `cert-authority` line from `/home/lio-team/.ssh/authorized_keys` using the independent Mac login below. Removing the GitHub secret stops new issuance. Existing sessions retain their privileges.

**Agents on the team Mac.** Sessions running as the macOS user `bakolas` can use the existing local SSH identity without signing into Google Cloud. This command was verified on 22 November 2026. Omit `'hostname && id -un'` for an interactive shell.

```sh

  -o HostKeyAlias=compute.4224439512231543992 -o StrictHostKeyChecking=yes \
  -o UserKnownHostsFile=~/.ssh/google_compute_known_hosts \
  bakolas@34.154.38.26 'hostname && id -un'
```

**Agents on other machines.** A VM administrator can install each teammate's SSH **public** key in a dedicated Linux account's `~/.ssh/authorized_keys`. This works without Google Cloud IAM membership. Send the administrator your `.pub` file and requested Linux username. If you need a key, run `ssh-keygen -t ed25519` and choose an unused local filename. Keep the private key on the machine that generated it. Use the confirmed username and your matching private key path in the command below.

```sh
ssh -i ~/.ssh/id_ed25519 -o IdentitiesOnly=yes -o HostKeyAlgorithms=ssh-ed25519 USERNAME@34.154.38.26
```

The VM's public host key is checked in at [deploy/backend/vm_known_hosts](deploy/backend/vm_known_hosts). From the repository root, pass `-o UserKnownHostsFile=deploy/backend/vm_known_hosts -o StrictHostKeyChecking=yes` to verify its identity on the first connection.
